## 2. OpenFic 设计卡片

### 卡片 A：视觉气质

- 关键词：轻、克制、文字优先、信息密度适中、工具感强。页面大面积使用白色与接近白色的灰；边界主要由 `1px` 分隔线建立，而不是浮起的大阴影卡片。
- 默认 Classic 浅色主题的背景为 `#ffffff`，典型灰阶从 `#fcfcfc`、`#f9f9f9`、`#f0f0f0` 到正文近黑 `#202020`。默认 Classic 深色背景为 `#111111`，文字接近 `#eeeeee`。OpenFic 的多主题功能允许其他强调色，但默认视觉并非紫色。
- 强调色主要承载当前选择、主要动作、链接和焦点。成功、警告、失败等业务状态应另用语义色，且同时显示文字。
- 阴影节制，仅用于浮层、弹窗或封面；普通面板靠底色、边线与留白分层。

### 卡片 B：排版与节奏

- OpenFic 全局字体优先中文衬线变量字体，再回退到中文无衬线与系统字体；代码/数字另有等宽字体。它在正文工作区使用 16px 与 1.8 行高。
- NovelAgent 不必照抄全局衬线：建议**工具界面用系统无衬线，小说正文用宋体/思源宋体/Georgia 回退栈**，避免当前密集表单和统计数字失去辨识度。
- 建议迁移刻度：微文案 12px、说明 13px、常规界面 14px、主按钮 14px、正文 16–18px、页面标题 24–28px；正文行高 1.8–2.0。当前多处 9–11px 文本需优先提高可读性。
- 间距以 4px 为基础刻度：4/8/12/16/24/32。工作台同级信息优先靠间距和边线分组，减少“卡片套卡片”。

### 卡片 C：布局与导航

- OpenFic 的桌面左侧是常驻工具轨，展开后显示名称；写作场景再设章节目录、中央正文和右侧上下文/助手区。中心内容是主角，辅助面板为它让位。
- NovelAgent 对应方案：桌面宽屏先使用 64px 图标轨与 232px 展开态；导航图标须附可读名称、`aria-label`/`title`，默认展开还是收起可根据可用宽度决定。左轨无需复制 OpenFic 的业务入口。
- 创作控制台及表单遵循“页头 → 核心状态/主操作 → 次级信息”的顺序。阅读页遵循“目录 → 正文”，长文本居中、限制阅读行宽；长期记忆遵循“列表 → 详情”。
- 底部窄状态区可承载现有离线/在线、连接和任务进度信息；不要让状态只用小绿点表达。

### 卡片 D：组件与状态

- 导航、列表项、标签、表单和弹层使用统一的 hover、selected、focus-visible、disabled、loading 规则。选中态采用淡背景和清楚的文字/边线，减少大面积高饱和填充。
- 按钮三层：主操作为高对比实底；普通操作为低对比边框或浅底；危险操作为语义红色且保留现有确认流程。一个局部区域原则上只突出一个主按钮。
- 章节和人物列表采用整行可点区域、明确的选中标记、名称与辅助信息两级层次。空态应解释下一步行动；错误与加载态要在原位显示，不只依赖全屏遮罩。
- OpenFic 的轻量动效是 150–240ms 的颜色/位移过渡；NovelAgent 仅在导航、面板和浮层需要时使用，遵守 `prefers-reduced-motion`。避免给频繁更新的正文和统计数据加持续动画。

### 卡片 E：边界与适配

- 参考项目的主题系统、React 组件、富文本编辑器与助手侧栏是具体实现，不属于本次必须移植的功能。NovelAgent 的阅读页是阅读现有正文，不能被误改为可编辑正文。
- OpenFic 的截图为桌面宽屏视觉。NovelAgent 仍要覆盖平板和手机；移动端避免 64px 左轨挤压内容，应提供可触达的导航和回到列表的入口。
- 图标优先使用本地内联 SVG 或现有字符图标的统一替换，样式与语义一致即可；不要依赖外链图标库。

## 5. Cursor 实施顺序

### 阶段 0：建立基线

1. 读取 `AGENTS.md`、三个前端入口文件和 `docs/USER_GUIDE.md`，记录所有 `id`/`data-*`/表单名称的依赖。读 `app.js` 中动态生成的章节、人物、时间线、研究卡、统计图 HTML，不只看静态页面。
2. 启动当前站点，采集桌面（建议 1440×900）、平板（约 768×1024）、手机（约 390×844）的五个视图截图；尽量包含有项目和空项目两种状态。若运行环境没有样例数据，不要为了截图调用线上模型或创建真实付费任务；用现有可用数据及离线方式验证。
3. 对照参考 `demo.png`，列出 NovelAgent 当前与目标的差异：布局、颜色、字号、表单、列表、正文、状态、响应式。保存基线，后续每阶段用相同视口复拍。

### 阶段 1：基础令牌和全局骨架

1. 建立第 3 节语义令牌，统一字体、文字颜色、背景、边线、控件圆角、间距。将现有 `--violet` 等只保留给兼容或语义用途，逐步去除对业务卡片的硬编码色。
2. 重做 `.shell`、`.sidebar`、`nav`、`.nav-item`、`.topbar`、`main`。桌面可采用默认展开的 232px 侧栏；若实现 64px 收起态，需有显式按钮、持久化选择和键盘标签。宽屏主内容不要无限拉长；窄屏保留导航可见且不横向溢出。
3. 统一 button、input、select、textarea、chip、badge、panel、flash、busy 的状态。为 `:focus-visible` 提供不依赖颜色填充的可见焦点。处理禁用、加载、错误和高对比状态。
4. 检查所有旧色值：在线/离线、READY、FAILED、警告、危险删除、图表输入/输出，避免被黑白化后失去区分。

### 阶段 2：页面按业务优先级改造

1. **阅读页先行**：目录/正文分区、正文排版、版本标签、章节列表状态；这是最能体现 OpenFic 风格的页面。不要加入编辑能力。
2. **控制台**：项目主信息、动作层级、指标和工作流/章节列表；主按钮根据业务状态保持唯一且明显。
3. **创建与方案工作台**：字段分组、chip、版本双栏与响应式折叠。
4. **长期记忆**：人物列表/详情、世界/时间线/资料，确保长内容可滚动且不被固定高度裁切。
5. **系统设置**：Token 图表、周期弹层和偏好表单。每完成一页，手动走通该页原有操作再进入下一页。

### 阶段 3：响应式、可访问性与文档

1. 建议断点：≥1200px 使用完整工作台；768–1199px 收紧左右栏；<768px 使用单列与可触达导航。对 `#readerView` 和 `#characterBrowser` 单独设计手机“列表/详情”转换，保证返回路径。
2. 检查长书名、长章节名、超长方案、空状态、失败状态、系统缩放 200%、键盘 Tab 顺序、焦点可见性、对话/弹层溢出。动效增加 `prefers-reduced-motion` 分支。
3. 如 UI 操作或状态呈现变化，更新 `docs/USER_GUIDE.md` 对应步骤和截图说明；再次验证 README 链接。
4. 仅在浅色主题全部验收后，按第 3 节考虑深色主题；若没有完整验收时间，把深色主题留作独立后续任务，不交付半成品开关。

## 6. 验收清单

### 视觉

- 五个视图形成统一的灰阶底色、细边线、克制强调和文字层次；没有深蓝侧栏与大面积紫色卡片残留，也没有大量叠加的无意义阴影。
- 桌面阅读页的目录和正文层次接近 OpenFic 示例图的“侧栏工具 + 中央阅读”关系；正文不贴边、不无限宽；手机正文仍有舒适内边距。
- 统计数字、状态文案和小说正文均易读。常规说明文字不再依赖 9–10px 字号。长内容、长标题不会覆盖按钮或产生全局横向滚动。
- 空态、加载态、失败态、禁用态、当前选中态在桌面与手机都可辨认；颜色之外有文字或形状线索。

### 功能回归

- 五个导航入口、切换项目、刷新与服务不可用提示正常。
- 创建小说、标签联动、方案确认、手工编辑、按反馈重做、版本比较/恢复正常。
- 生成、暂停/继续、修复、删除确认、章节浏览、历史草稿、打回重做正常；危险动作确认文本与范围保留。
- 人物选择/重建、手机返回列表、世界规则/时间线/资料展示正常。
- Token 周期快捷项、年月选择、图表和用量卡片，设置保存正常。

### 技术与交付

- `git diff` 只包含与前端视觉/必要交互、用户手册相关的改动；无无关后端或依赖迁移。
- 不改变 HTTP API 路径和返回结构；无新增外部网络字体、图标或脚本依赖。
- 运行项目现有相关测试；至少在桌面、平板、手机视口逐页验证，并给出每页改造后截图。测试结果要注明通过、未通过或因环境不能运行。
- 交付摘要写明：改了哪些文件、设计卡片哪些规则被采用、保留了哪些原业务行为、还有哪些具体未解决问题。不得只报告“样式已优化”。
